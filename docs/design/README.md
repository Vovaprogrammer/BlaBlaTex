# Дизайн BlaBlaTex

## F0.2 — макеты v1

Пакет для согласования перед этапом 1. Это статичные макеты, а не работающие
страницы приложения. Изменений в `frontend/` и контрактах нет.

За основу взяты предоставленные разработчиком референсы рабочего окна, регистрации,
списка проектов, профиля и отдельный образец логотипа. Основная палитра — **регистрация**:
нейтральные тёмные поверхности, светлые поля на экранах входа и фиолетовые акценты.
Расположение блоков остальных экранов следует соответствующим референсам.

### Поведение и необходимые отличия от картинок

- Вход: email и пароль. Регистрация: email, пароль от 8 символов, повтор пароля,
  обязательное согласие на обработку персональных данных. Username не нужен API;
  повтор пароля проверяется на фронте и не отправляется в API.
- Успешная регистрация создаёт сессию и пустой профиль; следующий экран — профиль.
  Фамилия, имя и отчество редактируются отдельными полями, как в ProfileUpdate.
  Пустое отчество допустимо. Email и роль отображаются из текущего пользователя,
  но не редактируются через PUT /profile.
- Профиль разделён на просмотр и редактирование. Кнопки «Отменить» и «Сохранить»
  находятся в режиме редактирования, а не в режиме просмотра.
- В карточках проектов используются название, тип, шаблон и дата изменения из API.
  Статусов «черновик/готов», описания, счётчика файлов, избранного и корзины в текущем
  ProjectOut нет. Такие поля и разделы не добавляются в API ради референса.
  Надпись «Изменён недавно» в макете — образец размещения даты, при реализации
  вместо неё выводится updated_at. Образцы названий — демонстрационные подписи.
- Поиск, сортировка и представление карточками/списком относятся к интерфейсу;
  конкретный объём реализации определяется F1.3, без новых контрактов.
- Пункты «Недавние», «Шаблоны» и «Аккаунт» показывают направление навигации из
  референсов. Наличие подписи в макете не добавляет самостоятельный маршрут или
  новую возможность бэкенда; состав меню этапа 1 уточняется при реализации.
- «Скачать PDF» показывается в контексте выбранного проекта, а не в общем списке
  или профиле: там не выбран документ для скачивания.
- Создание проекта этапа 1 — диалог с названием, выбором шаблона и динамическими
  полями, как предусматривает F1.3. Полный мастер с материалами остаётся F2.5.
- Поля создания проекта поступают из fields[] выбранного шаблона; их имена и значения
  на макете — заглушки, а не новый фиксированный контракт. Полный мастер этапа 2:
  тип → шаблон → поля → материалы. Лабораторная доступна, ВКР/статья/презентация — «скоро».
- Рабочее окно по указанию разработчика: слева переключение «Файлы / Чаты»,
  в центре выбранный чат, справа PDF и вкладки файлов. Заголовок слева — имя проекта.
  Сверху рядом с логотипом — выбор проекта. meta.tex только для чтения.
- **Предложение, ещё не утверждённое:** вкладка PDF незакрываемая, всегда первая.
  Остальные вкладки закрываются. Мобильная раскладка: «Файлы / Чат / PDF»;
  внутри правого раздела остаются вкладки PDF и исходников. Нужен отдельный выбор
  чатов проекта: несколько чатов пока не предусмотрены текущим API.
- PDF и сообщения в макете рабочего окна — схемы размещения, не реальные результаты
  сборки и не обещание существующих действий агента.
- Настройки ключа ИИ и токенов MCP относятся к разным будущим этапам. Изображение
  `••••last4` — обозначение маски, не настоящий ключ. Реальный ключ показывает только
  последние четыре символа, токен MCP отображается полностью один раз при создании.

### Состояния для последующей реализации

| Экран | Что проверить помимо основного вида |
|---|---|
| Вход и регистрация | Пустые поля, неверный email, короткий пароль, несовпадение паролей, отсутствие согласия, серверная ошибка, отправка, повторный email, неверный пароль |
| Профиль | Пустой профиль после регистрации, длинные поля, сохранение, ошибка сохранения, отмена |
| Проекты | Пустой список, загрузка, ошибка, длинное название, переименование, подтверждение удаления |
| Создание | Загрузка шаблонов, нет шаблонов, string/int/text/select, обязательные поля и default, серверные ошибки |
| Рабочее окно | Нет PDF, идёт сборка, ошибка сборки, конфликт файла, блокировка агентом, пустой чат |
| Настройки | Нет ключа/токенов, добавление, замена, удаление или отзыв с подтверждением по соответствующей задаче |
| Мобильная раскладка | Узкое окно, длинное имя проекта, клавиатура ввода, переключение панелей, доступ к файлу и возврат к PDF |

Это перечень состояний, а не утверждение, что они уже отрисованы или реализованы.

### Проверка разработчиком и командой

1. Сравнить вход/регистрацию с референсом регистрации: фон, карточка справа,
   светлые поля и фиолетовая кнопка. Проверить знак логотипа.
2. Сравнить проекты и профиль с соответствующими референсами: шапка, левая панель,
   расположение карточек и основных действий. Учесть отличия из списка выше.
3. Открыть оба варианта рабочего окна. Подтвердить расположение редактора справа
   и выбрать способ возвращения к PDF.
4. Отдельно согласовать черновики создания, мастера, настроек и мобильной раскладки.
5. Перед началом этапа 1 подтвердить комплект в команде, как требует F0.2.

**Статус: подготовлено к согласованию.** Макеты и черновики не считаются автоматически
утверждёнными из-за открытия PR. После правок потребуется подтверждение разработчика;
ссылка на общую доску Figma/Miro может быть добавлена отдельно.

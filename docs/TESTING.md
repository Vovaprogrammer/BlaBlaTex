# Проверки A1.1 — LLM-слой

## Конфигурация и использование

`LLM_PROVIDERS` — JSON-объект `{имя: {base_url, api_key, timeout, models}}`.
В `models` обязательны роли `main`, `fast`, `vision`; каждая содержит `name`,
`input_price` и `output_price` — неотрицательные цены в USD за миллион токенов.
Цены задаются явно; `timeout` — положительное число секунд, по умолчанию 30.
Ключ допускается пустым для работы со своим ключом пользователя.

`LLM_DEFAULT_PROVIDER` выбирает имя из объекта, `LLM_FALLBACK_PROVIDER` — необязательный
резерв. После смены окружения перезапустить API/воркер. Без LLM-настроек API продолжает
работать, но `get_model` сообщает о недостающей конфигурации.

`get_model(role, user_key=None)` создаёт свежую модель. Использовать внутри
`async with Agent(get_model("main")) as agent`, чтобы закрыть HTTP-клиенты после прогона.
Резерв вызывается при HTTP 5xx или таймауте; повторы SDK отключены. При 4xx переключения
нет. После начала выдачи потокового ответа резерв не подменяет частичный ответ.
Со своим ключом используется только основной провайдер: ключ не уходит резервному,
расход не переключается на ключ сервиса. Учёт расхода и подключение агента — следующие задачи.

PydanticAI Slim закреплён на 2.66.0; API проверен по установленному пакету и
[официальной документации FallbackModel](https://pydantic.dev/docs/ai/api/models/fallback/).

## Команды

Из `backend/`, Python 3.12, uv 0.13.6 (локально доступен через `uvx --from uv==0.13.6 uv`):

```sh
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest tests/test_llm_config.py tests/test_llm_models.py -q
uv run --locked python -m app.scripts.export_openapi --check
uv run --locked python -m app.scripts.export_template_schema --check
```

Полный набор требует Postgres 17 и Redis 7 из compose, настройки `POSTGRES_*` и
`REDIS_URL`/`REDIS_PORT`. В Linux: `uv run --locked pytest -q -k 'not env_example'`.
Тест чтения `.env.example` исключён; реальные `.env` в проверках не использовались.
Четыре проверки настоящего компилятора исключаются стандартной настройкой pytest.

## Результаты 07.11.2026

- До правок: Ruff и форматирование прошли, 94 профильных теста прошли.
- Коммит настроек: 105 профильных тестов и 1135 тестов в Linux прошли.
- Фабрика: 35 тестов настроек и моделей прошли; вызовы внешних моделей запрещены.
- Настоящий SDK против временного HTTP-стенда на `127.0.0.1`: пять сценариев прошли —
  503 → резерв, тот же сценарий с потоком, таймаут → резерв, 401 без резерва,
  пользовательский ключ + 503 без резерва. Авторизация проверена синтетическими ключами.
- Полная итоговая проверка Linux: **1159 passed, 5 deselected**, 75,20 с;
  Ruff, форматирование и проверки свежести обеих схем прошли.

На macOS полный набор дал 1119 успешных тестов и 16 сбоев извлечения документов:
существующий `resource.setrlimit(RLIMIT_AS, ...)` завершился `ValueError: current limit
exceeds maximum limit`. Извлечение не менялось; в Linux те же проверки прошли с исходным
лимитом памяти. Реальные LLM-провайдеры, их качество, цены и сборка PDF здесь не проверялись.

# Шаблоны, требования и проверка на реальных материалах — задачи

**Кто делает:** Вершинина Кристина работает без ИИ-агента — общается с вузом (требования МТУСИ, пилот) и делает простые задачи. Сложную разработку шаблонов — T-задачи с кодом или CI (T1.2–T1.4, T2.1, T2.3, T3.4, T4.3) — делает Чистяков Владимир.
**Зона:** `templates/`, `docs/requirements/`, `docs/templates.md`, `docs/checks.md`, тексты для пользователей, данные для eval (вне репозитория), пилот со студентами.
**Перед любой задачей** агент читает `AGENTS.md`, `docs/architecture.md` (разделы 6, 7, 9.5, 9.6 — всегда) и `docs/tasks/README.md`.

Общие правила зоны:
- Движок — XeLaTeX. Код — `listings`; `minted`, shell-escape, `inputenc` и `fontenc[T2A]` запрещены.
- Шрифты — только те, что есть в образе компилятора: Liberation Serif, Sans и Mono.
- Макросы класса `mtuci-report` только добавляются. Существующие не переименовываются и не меняют поведение — иначе сломаются старые проекты.
- Данные студента — только через `\bbt...` из `meta.tex`. В шаблонах нет настоящих ФИО.
- Проверка сборки: `docker compose run --rm compiler check-template templates/<slug>`.
- Реальные методички, отчёты и скриншоты студентов не коммитятся. Они лежат в общей закрытой папке команды и обезличены.

### T0.1 Требования МТУСИ к оформлению отчётов
**Ветка:** `docs/t0.1-requirements`

Решения 2026-11-09:
- лабораторные и другие учебные отчёты оформляются по методичке МТУСИ по ВКР бакалавра;

- вуз заранее не спрашиваем: делаем сами, поправят — меняем;
- титульник лабораторной собираем сами по бланку титульника ВКР.

Вместе с T0.1 написаны черновики `vkr.md` (часть T4.2) и `slides.md` (основа T4.3).

**Коммиты:**
1. `docs(requirements): report formatting requirements` — файл `docs/requirements/report-formatting.md`. Для каждого пункта — значение и источник: методичка МТУСИ по ВКР бакалавра; где она молчит — ГОСТ 7.32-2017; если нет и там — решение команды. Что описать:
   - поля страницы, шрифт и кегль, межстрочный интервал, абзацный отступ, выравнивание;
   - заголовки разделов и их нумерация, нумерация страниц;
   - подписи рисунков и таблиц: формат, место, нумерация;
   - листинги кода, формулы, перечисления;
   - титульный лист — точный текст и расположение; образец без персональных данных;
   - список источников (ГОСТ Р 7.0.100-2018), приложения.
2. ~~`docs(requirements): disciplines for first templates`~~ — отменён 2026-11-09: шаблон лабораторной один на все предметы.

**Готово, когда:** по документу можно сверстать отчёт, не заглядывая в методички.

### T3.5 Ссылка на пункт задания
**Ветка:** `fix/t3.5-enumerate-ref` · **Зависит от:** T1.2 · **Контекст:** 9.6

Находка сквозной проверки этапа 2 (PR #68). Ссылка `\ref` на пункт перечисления выводит букву со скобкой «в)», поэтому в отчёте фраза «(пункт~\ref{…})» превращается в «(пункт в))» — две скобки подряд. В `templates/_shared/mtuci-report.cls` у первого уровня `enumerate` задано `ref=\bbt@asbuk*)`, у второго — `ref=\arabic*)`.

`docs/requirements/report-formatting.md` (раздел 8) описывает только вид самого пункта («а)», «1)»), а формат ссылки на него — нет. По `AGENTS.md` поведение существующего в классе не меняем без согласования: новый формат ссылки сначала согласовать с человеком, при необходимости сверить с методичкой ВКР.

**Коммиты:**
1. `fix(templates): reference list items without closing bracket` — формат ссылки на пункт без скобки (настройка enumitem в классе); проверить и второй уровень.

**Готово, когда:** `docker compose run --rm compiler check-template templates/mtuci-lab` проходит, и в превью получается «(пункт в)».

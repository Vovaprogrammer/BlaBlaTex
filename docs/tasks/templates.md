# Шаблоны, требования и проверка на реальных материалах — задачи

**Владелец:** Вершинина Кристина. **Ревьюер по умолчанию:** Бирук Павел (связка с промптами); по CI — Чистяков Владимир.
**Зона:** `templates/`, `docs/requirements/`, `docs/templates.md`, `docs/checks.md`, тексты для пользователей, данные для eval (вне репозитория), пилот со студентами.
**Перед любой задачей** агент читает `AGENTS.md`, `docs/architecture.md` (разделы 6, 7, 9.5, 9.6 — всегда) и `docs/tasks/README.md`.

Общие правила зоны:
- Движок — XeLaTeX. Код — `listings`; `minted`, shell-escape, `inputenc` и `fontenc[T2A]` запрещены.
- Шрифты — только те, что есть в образе компилятора: Liberation Serif, Sans и Mono.
- Макросы класса `mtuci-report` только добавляются. Существующие не переименовываются и не меняют поведение — иначе сломаются старые проекты.
- Данные студента — только через `\bbt...` из `meta.tex`. В шаблонах нет настоящих ФИО.
- Проверка сборки: `docker compose run --rm compiler check-template templates/<slug>`.
- Реальные методички, отчёты и скриншоты студентов не коммитятся. Они лежат в общей закрытой папке команды и обезличены.

## Этап 0 — подготовка

### T0.1 Требования МТУСИ к оформлению отчётов
**Ветка:** `docs/t0.1-requirements`

**Коммиты:**
1. `docs(requirements): report formatting requirements` — файл `docs/requirements/report-formatting.md`. Для каждого пункта — значение и источник (методичка, кафедра или ГОСТ 7.32-2017, если вуз не задаёт своё). Что описать:
   - поля страницы, шрифт и кегль, межстрочный интервал, абзацный отступ, выравнивание;
   - заголовки разделов и их нумерация, нумерация страниц;
   - подписи рисунков и таблиц: формат, место, нумерация;
   - листинги кода, формулы, перечисления;
   - титульный лист — точный текст и расположение; образец без персональных данных;
   - список источников (ГОСТ Р 7.0.100-2018), приложения.
2. `docs(requirements): disciplines for first templates` — 3 дисциплины для первых шаблонов (предложение: СиАОД, ИТиП/Java, МОБД/PostgreSQL), их преподаватели и особенности отчётов: что обязательно, типичная структура, есть ли свой титульник.

**Готово, когда:** по документу можно сверстать отчёт, не заглядывая в методички.

### T0.2 Комплекты для бенчмарка
Не код. 3–5 комплектов: методичка, задание, код, скриншоты и, если есть, хороший готовый отчёт. Комплекты обезличить и положить в закрытую папку команды. Нужны Бируку для A0.1 как можно раньше: без них не выбрать провайдера.

Отдельно — слепая оценка текстов из бенчмарка по шкале 1–5 (A0.1, коммит 3).

**Ветка:** `docs/t1.1-template-guide` · **Вместе с:** A1.2, коммит 1 · **Контекст:** 7, 9.5, 9.6

**Коммиты:**

**Готово, когда:** Бирук и Чистяков подтвердили, что схема совпадает с `TemplateManifest`.

### T1.2 Общий класс mtuci-report
**Ветка:** `feat/t1.2-mtuci-report-class` · **Зависит от:** T0.1; для проверки сборки — B1.4 (до этого — локальный TeX Live или Overleaf с XeLaTeX) · **Контекст:** 6, 9.6

Файл: `templates/_shared/mtuci-report.cls`.

**Коммиты:**
1. `feat(templates): page layout, fonts and spacing` — по `report-formatting.md`:
   - `geometry`;
   - `fontspec` с Liberation Serif и Liberation Mono;
   - `babel` с русским языком;
   - интервал и абзацный отступ, отступ у первого абзаца;
   - нумерация страниц.
2. `feat(templates): headings, numbering and captions` — заголовки по требованиям; подписи «Рисунок N — …» и «Таблица N — …» в нужном месте; нумерация сквозная или по разделам — как требует вуз.
3. `feat(templates): title page from meta macros` — `\bbtTitlePage` использует только `\bbt...` из 9.6. Если поля нет — пустое место, а не ошибка: макросы объявляются со значениями по умолчанию через `\providecommand`.
4. `feat(templates): high-level macros for figures, code and tables` — `\bbtScreenshot`, `\bbtCodeFile`, окружения `bbtcode` и `bbttable` строго с сигнатурами из 9.6. Для `listings` — стиль, моноширинный шрифт, перенос длинных строк, кириллица в комментариях кода.
5. `docs(templates): class reference with examples` — раздел в `docs/templates.md` с каждым макросом и примером. Этот текст попадает в промпт агента, поэтому он короткий и точный.

**Готово, когда:** тестовый документ со всеми элементами (титул, разделы, рисунок, таблица, листинг из файла, листинг текстом, формула, список) собирается без ошибок и визуально совпадает с образцом кафедры. Сравнение показать команде.

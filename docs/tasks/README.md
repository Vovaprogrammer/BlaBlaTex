## Этапы

Работаем без спринтов и дат. Этап — это результат, который можно показать. Этап закрыт, когда сценарий из таблицы работает целиком в `develop`. Задачи следующего этапа можно брать раньше, если их зависимости уже выполнены.

| Этап | Результат |
|---|---|
| 0 | Репозиторий, CI, правила для агентов, выбор LLM-провайдера, требования к оформлению |
| 1 | Регистрация → проект из шаблона → правка `main.tex` → PDF |
| 2 | Загрузил материалы → «сделай отчёт» в чате → PDF; diff и откат правок ИИ |
| 3 | MVP: отчёт по реальным материалам без ручной вёрстки. Пилот на студентах проводит вуз после передачи, когда — неизвестно |
| 4 | Русло 2: «сделай отчёт по ЛР 3» в своём агенте (Claude Code, Codex, Cursor, opencode) → PDF в папке |
| 5 | ВКР, статьи и презентации: требования, шаблоны, импорт DOCX, библиография, проверка преподавателем, сравнение версий, нормоконтроль |

Сейчас закрываем этапы 0–4. Закрывает их наша итоговая проверка всего сценария и ревью всего кода (T3.2), а не пилот. Задачи этапа 5 описаны крупно и детализируются, когда до них дойдёт очередь; T5.1 и T5.2 уже описаны полностью, их можно брать раньше.

## Как устроена задача

ID задачи: `<зона><этап>.<номер>`. Зоны: B — бэкенд, F — фронтенд, A — ИИ/MCP, T — шаблоны. Например, `B1.3` — бэкенд, этап 1, задача 3.

**Задача = одна ветка = один PR.** Внутри задачи — список коммитов: агент делает их по порядку, и PR удобно читать по коммитам.

Поля задачи:
- **Статус** — «не начата», «в работе — PR», «сделана — PR», «отменена». Ставит автор задачи: после открытия PR — отдельным коммитом в той же ветке (`AGENTS.md`, шаг 9). Каждый PR правит только строку своей задачи, поэтому конфликтов нет.
- **Ветка** — имя ветки от `develop`.
- **Зависит от** — что должно быть в `develop` до начала. Если зависимость ещё не готова — работай против заглушки или фейка и договорись с тем, кто её делает.
- **Контекст** — какие разделы `architecture.md` прочитать.
- **Коммиты** — сообщения коммитов и что в каждом.
- **Готово, когда** — проверяемые критерии.
- **Не делать** — частые ошибки и выход за рамки.

Размер PR — до ~400 изменённых строк без lock-файлов и сгенерированного кода. Если больше — задачу делим, предварительно обсудив.

## Как берём задачи

- **Что осталось** — строка «Статус» в каждой задаче; что сейчас в работе — открытые PR. Отдельной доски нет.
- **Порядок.** Берёшь верхнюю задачу своей зоны со статусом «не начата», у которой выполнены зависимости. Задачи, которые блокируют других (список ниже), — вне очереди.
- **Лимит.** В работе у человека — не больше двух задач.
- **Результат этапа** показываем команде и руководителю, когда этап закрыт.
- **Вопросы по контрактам** — сразу в общий чат.

## Кто кого блокирует

Эти задачи делаются в первую очередь. Сделанные зависимости из списка убираем; прошлые этапы — в истории git.

- **A3.1** (план отчёта) → A3.2. Экран плана (F3.1) работает на API с заглушкой и A3.1 не ждёт.
- **A2.5** (eval) → A3.4 → F3.4; коммит 3 (тестовая модель без сети) → F3.5 (e2e).
- **A3.5** (надёжность прогона) → A3.6 (расход токенов): обе правят прогон агента.
- **A4.1** → A4.2 → A4.3 → A4.4 → F4.1, коммит 2. Цепочка MCP не ждёт других зон.
- **T5.1** (требования к ВКР и статье) → T5.2. Это этап 5: этапы 0–4 от них не зависят.
- Остальные задачи этапов 0–4, в том числе **A0.1** (выбор модели для сервера вуза) → T3.2 (итоговая проверка и ревью) → B4.4, F4.3, T3.4 → этапы 0–4 закрыты. Пилот вуза их закрытия не ждёт.

## Подготовка рабочего места (один раз)

1. `git config user.name` и `git config user.email`. Email должен быть привязан к твоему GitHub-аккаунту — коммиты агента идут от твоего имени.
2. `git config core.hooksPath .githooks` — включает хук, который вырезает строки об авторстве ИИ.
3. Установить GitHub CLI и выполнить `gh auth login` — через него агент открывает PR от твоего имени.
4. Запустить Claude Code в корне репозитория и подтвердить доверие к папке. Без этого не применяются разрешения из `.claude/settings.json`. Проверка — `/status`: в «Setting sources» есть «Shared project settings».
5. Не включать в личных настройках атрибуцию обратно. `.claude/settings.local.json` и `~/.claude/settings.json` не должны задавать `attribution`.

## Как дать задачу агенту

Новый чат на каждую задачу. Промпт:

```
Задача B1.3 из docs/tasks/backend.md.
Прочитай AGENTS.md, нужные разделы docs/architecture.md и саму задачу.
Сначала покажи план по коммитам из задачи — какие файлы, что в каждом коммите. Код не пиши, пока я не одобрю.
Потом сам создай ветку, делай по одному коммиту (код + тесты → линтер и тесты → коммит) и коротко отчитывайся после каждого.
В конце — /code-review develop...HEAD, исправь находки, запушь ветку и открой PR в develop по шаблону. Пришли ссылку.
Если чего-то не хватает в контрактах или задача противоречит architecture.md — остановись и спроси.
```

## Ревью кода

1. **Агент проверяет себя до PR:** `/code-review develop...HEAD`. Цель указывается явно: без неё ревью сравнивает с удалённой веткой и может пропустить запушенные коммиты.
2. **PR** открывает агент от имени автора задачи. Автор отвечает за каждую строку, даже написанную агентом.
3. **Ревью человеком — по желанию**, approve не нужен. Нужен второй взгляд — попроси в общем чате или запусти `/code-review <номер PR> --comment`: находки появятся комментариями к строкам. Если ревью было, замечания автор передаёт своему агенту: «исправь замечания из PR #N».
4. **Merge** делает человек: «Rebase and merge» после зелёного CI (включая `no-ai-attribution`), чтобы атомарные коммиты остались в истории.

Чего не делать, чтобы Claude не попал в contributors:
- не просить `@claude` в GitHub что-то закоммитить;
- не давать GitHub Action Claude права на запись.

Коммиты от GitHub-приложения идут от `claude[bot]` и попадают в contributors. Ревью через Action только оставляет комментарии (права `contents: read`) и на contributors не влияет.

## Definition of Done

- [ ] Все коммиты из задачи; каждый проходит линтер и тесты.
- [ ] Тесты на новую логику. Бэкенд — pytest, фронт — vitest, сценарии — Playwright (с этапа 3).
- [ ] Критерии «Готово, когда» проверены руками или тестом.
- [ ] Контракты не менялись или обновлены отдельным коммитом (`architecture.md` + `openapi.json`).
- [ ] `/code-review` пройден, CI зелёный (включая `no-ai-attribution`).
- [ ] Нет секретов, персональных данных, `print`/`console.log`, закомментированного кода.
- [ ] Для промптов: в PR приложены результаты eval до/после. Пока нет eval (A2.5) — ручной прогон на 1–2 комплектах из закрытой папки: что было и что стало.
- [ ] Изменилось то, что видит студент, — поправлена помощь `frontend/src/features/texts/help.md`; изменилось, какие данные куда уходят, — ещё `privacy.md` и `consent.md` там же.
- [ ] Строка «Статус» задачи — «сделана» со ссылкой на PR.

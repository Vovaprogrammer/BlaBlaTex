# Шаблоны LaTeX

## Класс mtuci-report

Общий класс всех учебных отчётов МТУСИ: `templates/_shared/mtuci-report.cls`. Оформление — по [report-formatting.md](requirements/report-formatting.md). Стиль один на весь вуз, параметров у класса нет.

Класс сам задаёт:
- поля 30/10/20/25 мм;
- Liberation Serif 14 pt, полуторный интервал (30 строк на странице), абзацный отступ 1,25 см, выравнивание по ширине;
- номера страниц внизу по центру; на титульнике номера нет;
- оформление и нумерацию заголовков, подписей, формул, перечислений, списка источников и приложений.

В тексте отчёта шрифты, поля, интервалы и отступы не задаются. Пакеты оформления не подключаются.

### Документ

```latex
\documentclass{mtuci-report}
\input{meta}
\begin{document}
\bbtTitlePage
\input{sections/goal}
...
\end{document}
```

`meta.tex` создаёт бэкенд: макросы `\bbt...` из профиля и полей проекта (`architecture.md` 9.6). Класс заранее объявляет их пустыми. Если какого-то макроса в `meta.tex` нет, на его месте пусто, а сборка не падает.

### Макросы класса

| Макрос | Что даёт |
|---|---|
| `\bbtTitlePage` | титульный лист из `meta.tex` |
| `\bbtScreenshot[ширина]{путь}{подпись}{метка}` | рисунок с подписью «Рисунок 3.1 – подпись» под ним |
| `\bbtCodeFile[язык]{путь}{подпись}{метка}` | листинг из файла, подпись «Листинг 3.1 – подпись» над ним |
| `\begin{bbtcode}{язык}{подпись}{метка}` … `\end{bbtcode}` | листинг текстом |
| `\begin{bbttable}{подпись}{метка}` + `tabular` | таблица с подписью «Таблица 3.1 – подпись» над ней |

Общее для всех:
- номер в подписи ставит класс: в разделе 3 — «3.1», в приложении А — «А.1», в подразделе приложения — «А.1.2»;
- подпись пишется с прописной буквы, без точки в конце;
- метка нужна для ссылки `\ref{метка}`, её можно оставить пустой `{}`;
- на каждый рисунок, таблицу и листинг в тексте есть ссылка, она стоит до них.

**Рисунок.** Ширина — длина LaTeX, по умолчанию ширина текста. Выше 2/3 страницы рисунок не бывает, пропорции сохраняются. Он встаёт сразу после ссылки, а если места нет — наверху следующей страницы, и в чужой раздел не уходит. Форматы — PNG, JPG и PDF; SVG не вставляется.

```latex
Окно программы показано на рисунке~\ref{fig:window}.
\bbtScreenshot{materials/screen1.png}{Окно программы после запуска}{fig:window}
\bbtScreenshot[0.6\linewidth]{materials/schema.png}{Схема базы данных}{fig:schema}
```

**Листинги.** Liberation Mono 12 pt, без номеров строк, рамки и подсветки. Кириллица в комментариях и строках печатается как есть. Длинная строка переносится, а не обрезается. Язык можно указать или опустить: на вид он не влияет. В тексте — до ~40 строк кода, длиннее — в приложение.

```latex
Функция сортировки приведена в листинге~\ref{lst:sort}.
\bbtCodeFile[python]{materials/sort.py}{Функция сортировки}{lst:sort}

\begin{bbtcode}{sql}{Запрос к таблице заказов}{lst:orders}
SELECT id, total FROM orders WHERE total > 1000; -- заказы дороже 1000 рублей
\end{bbtcode}
```

Код в `bbtcode` начинается со следующей строки после `\begin{bbtcode}{…}{…}{…}`. Строка `\end{bbtcode}` пишется с начала строки.

**Таблица.** Внутри — один обычный `tabular`. В окружение `table` таблицу не оборачивают, иначе сборка упадёт. Таблица стоит там, где написана, и может перейти на следующую страницу. Тогда над продолжением слева печатается «Продолжение таблицы 3.1», а под ним повторяется шапка — первая строка таблицы вместе с линиями сразу под ней. Подпись — 14 pt, сама таблица — 12 pt. Сначала строка-шапка, потом данные.

```latex
Результаты замеров приведены в таблице~\ref{tab:time}.
\begin{bbttable}{Время сортировки массивов}{tab:time}
  \begin{tabular}{|r|c|c|}
    \hline
    Длина массива & Слиянием, мс & Встроенная, мс \\ \hline
    1000  & 0,2 & 0,1 \\ \hline
    10000 & 2,5 & 2,3 \\ \hline
  \end{tabular}
\end{bbttable}
```

### Обычный LaTeX: как выглядит

| Что пишем | Что получается |
|---|---|
| `\section{Цель работы}` | «1 Цель работы» — полужирный, с абзацного отступа. Разделы идут подряд, без новой страницы |
| `\subsection{…}`, `\subsubsection{…}` | «3.1 …», «3.1.2 …». Глубже трёх уровней не бывает |
| `\section*{Введение}` | «ВВЕДЕНИЕ» — прописными по центру, без номера |
| `\begin{itemize}` | пункты с «–» |
| `\begin{enumerate}` | «а)», «б)», … — когда на пункты есть ссылки; вложенный `enumerate` — «1)», «2)» |
| `\begin{equation}\label{eq:t} … \end{equation}` | формула по центру с номером «(3.1)» справа; ссылка — `\eqref{eq:t}` |
| `\[ … \]` | формула без номера, если на неё нет ссылок |
| `\cite{knuth}`, `\cite[с.~132]{knuth}` | «[1]», «[1, с. 132]» |
| `\begin{thebibliography}{9}` … `\bibitem{knuth} …` | с новой страницы «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ», записи «1. …» в порядке первой ссылки |
| `\appendix`, затем `\section{Название}` | каждое приложение с новой страницы: «Приложение А», под ним название |

Пункты перечисления — со строчной буквы, в конце `;`, у последнего — `.`.

Пояснение обозначений — сразу после формулы, без пустой строки. Каждое обозначение — с новой строки:

```latex
\begin{equation}\label{eq:time}
  T(n) = c \cdot n \log_2 n,
\end{equation}
где $T(n)$ – время сортировки, мс;\\
$c$ – постоянная, зависящая от компьютера;\\
$n$ – длина массива.
```

Ссылка на приложение — «(приложение~\ref{app:code})», где `app:code` — метка `\label` после `\section` приложения.

### Титульный лист

`\bbtTitlePage` печатает:
- шапку вуза;
- кафедру `\bbtDepartment`;
- «ОТЧЕТ» и под ним «по лабораторной работе № `\bbtLabNumber`», «по дисциплине «`\bbtDiscipline`»», «на тему «`\bbtLabTitle`»», «Вариант `\bbtVariant`»;
- строки «Студент гр. `\bbtGroup`» — `\bbtShortName` и «Преподаватель» — `\bbtTeacher`, у каждой линия для подписи;
- внизу «`\bbtCity` `\bbtYear` г.».

Вид работы берётся из поля `work_type` (`\bbtWorkType`): «Практическая работа» → «по практической работе», иначе — «по лабораторной работе». Если поле пустое, его строка не печатается, а место остаётся. Нет группы — просто «Студент», нет преподавателя — линия без фамилии.

### Проверка класса

Тестовый документ со всеми элементами — `templates/_class-test/` (не шаблон, студентам не виден):

```
docker compose run --rm compiler check-template templates/_class-test
```

Макросы класса только добавляются. Существующие не переименовываются и не меняют поведение. Служебные имена внутри класса — с `@` (`\bbt@...`), поэтому они не совпадают с макросами полей `\bbt<Key>`.

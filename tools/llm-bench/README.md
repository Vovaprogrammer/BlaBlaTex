# Бенчмарк открытых моделей

Конфигурация — JSON-список `name`, `base_url`, `model`, необязательного
`api_key_env` (имя переменной окружения) и пары цен `input_price`/`output_price`.
Ключи в файлы не записываются; для локальной модели имя переменной можно опустить.
HTTPS обязателен для внешних адресов; HTTP разрешён только для loopback.
Пример — `providers.example.json`. Инструмент сам не читает файлы `.env`.

```sh
uv sync --locked
uv run --locked python -m llm_bench.runner --config providers.json --provider local --scenario tool_calling
uv run --locked python -m llm_bench.runner --config providers.json --provider local --scenario section --input /path/to/material.txt --runs 1
uv run --locked python -m llm_bench.runner --config providers.json --provider local --scenario vision --input /path/to/screenshot.png --runs 1
```

По умолчанию каждый сценарий повторяется 10 раз; `--runs` задаёт количество,
`--timeout` — таймаут HTTP-запроса в секундах. Вывод — JSON в stdout, его можно
сохранить в закрытую локальную папку; тексты ответов могут содержать данные из
материалов. Инструмент отправляет указанные файлы выбранному серверу: перед
передачей внешнему провайдеру нужно согласовать конкретные данные и получателя.

Tool calling использует вымышленный `main.tex` и фейковые `read_file`, `edit_file`
и `compile`; успех — все три инструмента вызваны, файл точно исправлен и после
правки проверен фейковым компилятором. Это проверка работы с инструментами, а не
настоящая сборка LaTeX. На каждый прогон максимум восемь запросов к модели.
`section` читает UTF-8 материал, `vision` — PNG или JPEG. Сценарии не оценивают
качество ответа автоматически. Время, число входных и выходных токенов и
кешированных входных токенов записываются отдельно; недоступное значение — `null`,
а не ноль. При нескольких запросах метрика суммируется только если есть в каждом.
Отказ или таймаут записывается как ошибка; процесс возвращает ненулевой код.
Коды ошибок: `timeout` — истёк срок ожидания; `transport` — ошибка соединения;
`http_status` — отказ с HTTP-кодом в одноимённом поле; `invalid_response` —
некорректный ответ API; `invalid_input` — не удалось прочитать входной файл
или формат входа не поддерживается. Текст исключения и ответа сервера не сохраняется.

# Фронтенд BlaBlaTex

Node.js 24, pnpm 11.25.0. Все команды выполняются в `frontend/`.

```sh
pnpm install --frozen-lockfile
pnpm gen:api
pnpm dev
```

## API и демонстрационный режим

В `frontend/.env.local` установить `VITE_USE_MOCKS=1` и перезапустить dev-сервер.
Образец — `.env.example`. Приложение работает через MSW без бэкенда. Чтобы перейти
на настоящий API, заменить значение на `0` и перезапустить сервер. `/api` передаётся
на локальный бэкенд `:8000`; cookie отправляются автоматически.

Моки запускаются только при разработке, до отрисовки приложения. В production-сборке
они не подключаются. Демонстрационная сессия изначально открыта: `student@example.com`,
пароль `demo-password` — только фикстура, не настоящий аккаунт или секрет.
Данные хранятся исключительно в памяти, после перезагрузки возвращаются к исходным.
Нельзя использовать этот режим для работы с настоящими материалами или паролями.

Ответы соответствуют типам текущего `backend/openapi.json`; типы API не пишутся вручную.
Моки поддерживают основные операции этапа 1 и нужные UI сценарии 401/403/404/409/412/422.
Это демонстрационный набор данных, а не полная копия серверной логики или проверки
безопасности: сервер остаётся источником правил. Обновление профиля/полей увеличивает
версию `meta.tex`, но реальный LaTeX из данных студента не генерируется.

Мок сборки возвращает заранее подготовленную **пустую PDF-страницу**. Это не результат
компиляции пользовательских файлов. В логе это отмечено явно; реальные отчёты проверяются
с настоящим API и компилятором.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

`pnpm gen:api` обновляет `src/api/schema.d.ts`. CI проверяет свежесть этого файла.
Автоматические тесты используют MSW и не обращаются к настоящим сервисам.

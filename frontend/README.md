# Фронтенд BlaBlaTex

Node.js 24, pnpm 11.25.0. Все команды выполняются в `frontend/`.

```sh
pnpm install --frozen-lockfile
pnpm gen:api
pnpm dev
```

## API и тестовые данные

Обычный запуск работает с настоящим API: `.env.example` содержит `VITE_USE_MOCKS=0`.
Если ранее в `frontend/.env.local` было значение `1`, заменить его на `0` и перезапустить
dev-сервер. `/api` передаётся на локальный бэкенд `:8000`; cookie отправляются автоматически.
Запуск бэкенда и инфраструктуры описан в корневом README.

Для изолированных проверок интерфейса без бэкенда можно временно установить
`VITE_USE_MOCKS=1` и перезапустить сервер. Этот режим предназначен для тестирования.

Моки запускаются только при разработке, до отрисовки приложения. В production-сборке
они не подключаются. Демонстрационная сессия изначально открыта: `student@example.com`,
пароль `demo-password` — только фикстура, не настоящий аккаунт или секрет.
Данные хранятся исключительно в памяти, после перезагрузки возвращаются к исходным.
Нельзя использовать этот режим для работы с настоящими материалами или паролями.

Ответы соответствуют типам текущего `backend/openapi.json`; типы API не пишутся вручную.
Моки поддерживают основные операции этапа 1 и нужные UI сценарии 401/403/404/409/412/422.
Это демонстрационный набор данных, а не полная копия серверной логики или проверки
безопасности: сервер остаётся источником правил. Обновление профиля/полей увеличивает
версию `meta.tex`, но реальный LaTeX из данных студента не генерируется.

Мок сборки возвращает заранее подготовленную **пустую PDF-страницу**. Это не результат
компиляции пользовательских файлов. В логе это отмечено явно; реальные отчёты проверяются
с настоящим API и компилятором.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

`pnpm gen:api` обновляет `src/api/schema.d.ts`. CI проверяет свежесть этого файла.
Автоматические тесты используют MSW и не обращаются к настоящим сервисам.

## Проверка F1.1 в браузере

1. Включить демонстрационный режим и открыть `http://127.0.0.1:5173/projects`.
   Должна появиться оболочка с логотипом, боковым меню и заглушкой проектов.
2. Перейти между проектами, профилем и настройками; выбранный раздел выделяется.
3. Переключить тему, обновить страницу: настройка сохраняется.
4. Открыть `/login` и `/register`: показываются отдельные оболочки в стиле
   согласованного макета, ссылки между ними работают. Формы реализованы в F1.2.
5. Проверить ширину 320 px: логотип, кнопки и текст помещаются, меню переносится.
6. Выключить моки и перезапустить сервер. С настоящим API без сессии защищённые
   адреса переводят на вход; при недоступном API показывается ошибка с повтором,
   а не ложное сообщение о выходе. Сессия проверяется через `/auth/me`.

Ожидание сессии, её истечение, очистка кэша, повтор после 500 и гостевой доступ
также проверяются автоматическими интеграционными тестами. В F1.1 содержимое
проектов и рабочего окна остаётся заглушками; проекты и редактор реализуются
своими последующими задачами.

## Проверка F1.2

В обычном режиме (`VITE_USE_MOCKS=0`) нужен настоящий API на `:8000` и его база данных.
Используйте тестовый аккаунт и вымышленные данные.

1. Открыть `/register`: проверить неверный email, пароль короче 8 символов,
   несовпадение паролей и отсутствие согласия. Запрос не отправляется до исправления.
2. Зарегистрироваться с новым email. Откроется пустой профиль для заполнения.
   Username отсутствует, повтор пароля в API не отправляется. Ссылка «Текст согласия»
   открывает явно обозначенную временную заглушку до T3.3.
3. Заполнить данные профиля, сохранить, обновить страницу. Сессия и профиль должны
   сохраниться. В режиме просмотра есть «Изменить профиль»; отмена не сохраняет правки.
   Пустые строки допустимы по контракту, длина поля — до 200 символов.
4. Выйти. Прямой переход на `/profile` переводит на вход. Неверный пароль оставляет
   сообщение в форме, успешный вход возвращает на ранее запрошенную личную страницу.
5. Зарегистрироваться повторно с тем же email: серверное сообщение появится у email.
6. Проверить формы на широком экране и при ширине 320 px, переключить тему.

Автоматические тесты используют MSW. Отдельный тестовый dev-сервер для визуальной
проверки можно запустить с `VITE_USE_MOCKS=1` на другом порту. Его данные сбрасываются
после перезагрузки; сохранение настоящей сессии между перезагрузками проверяется
только с реальным API. Синтетический аккаунт фикстуры: `student@example.com` /
`demo-password`. Нельзя вводить реальные пароли и персональные данные в тестовом режиме.

## Проверка F1.4

Рабочее окно открывается по `/projects/<id>` существующего проекта. По умолчанию
запросы идут в настоящий API; создание и список проектов появятся в F1.3.

1. Проверить выбор проекта рядом с логотипом и три панели: файлы слева, чат в центре,
   документы справа. Перетащить разделители, обновить страницу: размеры сохраняются.
2. Создать текстовый файл и папку, переименовать файл через меню `…` или правую кнопку
   мыши, перенести в папку мышью. На сенсорном экране использовать пункт «Переместить».
   В нём указывается полный путь относительно корня проекта.
3. Попробовать создать существующий файл: содержимое не перезаписывается. Проверить
   неверное имя, например `.hidden`: сообщение сервера отображается в форме.
4. Удалить обычный файл: сначала требуется подтверждение. У `meta.tex` и папки с
   автоматическими файлами переименование, перенос и удаление недоступны.
5. Открыть файл: он показывается во вкладке справа. Повторное открытие не создаёт
   вторую вкладку. Переименование/перенос меняют путь вкладки, удаление закрывает её.
   PDF всегда первая вкладка и не закрывается. По вкладкам можно ходить стрелками,
   Home/End, Delete закрывает выбранный файл.
6. Сузить экран до 320 px: переключатели «Файлы / Чат / PDF». Открытие или создание
   файла переводит в правую панель. Проверить создание пустого файла, возврат к PDF,
   выбор проекта, светлую и тёмную тему.

Файлы пока доступны для чтения; полноценный редактор и автосохранение — F1.5.
PDF и чат обозначены честными заглушками до своих задач, результаты сборки и ответы
помощника не имитируются. Раздел материалов отделён в дереве; загрузка и просмотр
материалов — F2.4. Список чатов пока содержит только вход в чат проекта.

Для браузерных тестов с `VITE_USE_MOCKS=1` проект фикстуры доступен по адресу
`/projects/00000000-0000-4000-8000-000000000001`. Его файлы сбрасываются при перезагрузке;
сохранение размеров панелей при этом работает независимо от фикстур.

# Эталонные отчёты mtuci-lab

Вымышленные отчёты по лабораторным: по одному на каждую группу видов работ из указаний шаблона `mtuci-lab` (раздел «Ход работы» в `templates/mtuci-lab/template.yaml`). Они показывают, как должен выглядеть хороший отчёт: фрагменты кода с пояснениями, таблицы из материалов, анализ результатов, выводы.

**Кто читает:** люди — как образец, и будущий eval (A2.5, T2.4). Агенту эталоны не передаются: образец в каждом запросе к модели стоил бы 25–30 % дневной квоты студента. Всё полезное из эталонов уже есть в указаниях шаблона.

| Папка | Вид работы | Что показывает |
|---|---|---|
| `lab-algorithms` | алгоритмы с замерами | фрагменты кода, методика, таблицы замеров и счётчиков, график, рост времени против оценки сложности, ответы на контрольные вопросы |
| `lab-sql` | программы и инструменты (база данных) | схема БД, запросы листингами, результаты таблицами, разбор, почему результат именно такой |
| `lab-logic` | логика и автоматы | теоретическая часть по требованию методички, таблица истинности, СДНФ и минимальная ДНФ формулами, карта Карно, схема, проверка |
| `lab-circuit` | расчёт и моделирование | исходные данные варианта, расчёт формулами с подстановкой, таблица «расчёт — эксперимент — расхождение», график, причины расхождения |
| `lab-network` | настройка по шагам | команды, снимки экрана с 1–2 предложениями под каждым, таблица адресов, проверка связи |

## Устройство

Эталон — проект целиком, как его видит сервис:
- `main.tex` и `sections/` — как в шаблоне `mtuci-lab`: те же разделы и файлы;
- `meta.sample.tex` — вымышленный студент, при сборке становится `meta.tex`;
- `materials/` — вымышленные материалы: задание, код, данные, картинки. Код и SQL в них настоящие и запускались, а их вывод сохранён как есть.

Все числа в отчётах взяты из материалов. Числа, которые отчёт посчитал сам (отношения, частота среза), перечислены в тесте.

Папки на `_` реестр шаблонов пропускает, поэтому эталоны с картинками не копируются в проекты студентов.

## Проверка

```
docker compose run --rm compiler check-template templates/_examples/<папка>
```

Тест `backend/tests/test_template_examples.py`:
- эталон — проект из `mtuci-lab`: тот же `main.tex`, файлы всех разделов и макросы `meta.sample.tex`;
- проверки бэкенда не находят в эталонах ни ошибок, ни предупреждений, кроме посчитанных чисел из списка;
- с `pytest -m compiler` эталоны собираются настоящим компилятором, и ни одна строка, включая формулы, не вылезает за поле.

В PR каждый эталон собирает `check-template` в обязательной проверке `templates-build`, а тест со сборкой идёт в `compiler-test` (`docs/templates.md`, «Проверка шаблона»).

После правок класса, указаний шаблона или проверок эталоны должны оставаться зелёными.

Настоящие отчёты и методички студентов сюда не кладутся: темы, код, числа и картинки придуманы по образцу настоящих работ.
